# 카카오톡 자동화 사이드카 (kt.py)

카카오톡 PC 앱을 화면 조작으로 제어하는 독립 스크립트. `agent-desktop` 본체는 건드리지 않습니다.

## ★ 글쓰기(전송) — 안전 가드 6단계

```bash
python kt.py send "메시지" --to "방이름" --yes      # 실제 전송
python kt.py send "메시지" --to "방이름"            # dry-run (입력만, 자동 정리)
```

| 단계 | 가드 | 실패 시 |
|---|---|---|
| 1 | **방이 2개 이상 열려 있으면 `--to` 필수** | 중단 (오발송 방지) |
| 2 | 방 이름 유사도 대조 (≥0.5) | 중단 |
| 3 | 기준 크기 + 맨 아래(최신) 고정 | - |
| 4 | 입력 내용 검증 (붙여넣은 뒤 다시 읽어 대조) | 중단 |
| 5 | **새 메시지 도착 감지** (입력 전 스냅샷 비교) | 중단 |
| 6 | Enter 후 재읽기로 내 메시지 확인 | 경고 |

### ★ 입력창 정리 — Ctrl+A 는 안 통한다 (실측)

입력창을 비울 때 **`Ctrl+A` → `Delete`** 를 쓰면 안 됩니다.
카카오톡에서 `Ctrl+A`는 **입력창이 아니라 "대화 전체선택"** 으로 가서
입력창 글자가 그대로 남습니다. (실측: clear 후에도 `[RAON-CLEAR-TEST]...` 잔존)

→ **Backspace 200회 반복**(`clear_input`)으로 확실히 지웁니다.
→ dry-run 은 전송하지 않으므로 **반드시** 정리하고, 실패 시에도 정리합니다.

### 입력창 텍스트는 메시지로 오판되지 않는다

검증: 입력창에 `__DRYRUN_LEFTOVER__`를 넣고 읽기 실행 →
읽은 메시지 5건에 해당 문자열 **미포함**.
(`read`는 대화 본문을 클릭해 `Ctrl+A` 하므로 입력창 텍스트는 복사 대상이 아님)

## ★ 기준점 = 항상 맨 아래(최신)에서 위로 N건

"마지막 채팅부터 위로 30건"이 성립하려면 **스크롤이 맨 아래에 있어야** 합니다.
그래서 읽기 **전**과 **후**, 방 열기 **직후**에 `End` 키로 맨 아래로 복귀시킵니다.

```
[open]  → End (최신으로)
[read]  → End (기준 고정) → [load 회차] → 출력 → End (다음 읽기 대비)
```

### 왜 필요한가 (실측)

| 상태 | 결과 |
|---|---|
| 위로 5페이지 올려놓고 읽기 | ❌ 기준점이 흔들림 |
| `End` 복귀 후 읽기 | ✅ **최신 30건** 정확히 확보 |

검증: 일부러 PageUp 5회로 맨 위까지 올린 뒤 `read` 실행 →
`[read] 스크롤 맨 아래(최신)로 복귀` → 출력 마지막이 **오전 1:10 (최신)**,
스크린샷상 스크롤바가 맨 아래에 붙어 있음 확인.

## ★ 읽기 기본값 = 30건 (스크롤 단위와 일치)

PageUp 1회가 30건을 로드하므로, **읽기도 30건을 기본으로** 맞췄습니다.
로드된 건수가 30건에 못 미치면 **PageUp을 자동으로 더 눌러** 30건을 채웁니다.

```
[load] 0회차: 로드 10건 → 조건충족 10건 (목표 30)
[load] 1회차: 로드 10건 → 조건충족 10건 (목표 30)
[load] 2회차: 로드 40건 → 조건충족 40건 (목표 30)
[read] 로드 40건 → 출력 30건 / 자동스크롤 2회
```

- 방 열자마자 10건뿐이어도 → PageUp 2회 자동 → **30건 확보**
- 이미 40건 로드돼 있으면 → 스크롤 0회, 30건만 출력
- 증가가 2회 연속 없으면 전체 로드로 판정하고 중단
- `--max-scroll N`으로 자동 스크롤 상한 조절 (기본 10)

| 명령 | 출력 |
|---|---|
| `read` (옵션 없음) | **30건** |
| `read -n 15` | 15건 |
| `read -n 60` | 자동 스크롤해서 60건 확보 |
| `read --since 6` | 최근 6시간, 30건 목표 |

## ★ 스크롤은 키보드 PageUp / PageDown 으로 한다

마우스 휠이 아니라 **키보드 페이징 키**를 씁니다.

| 동작 | 키 | 코드 상수 |
|---|---|---|
| 위로 (이전 메시지 로드) | **PageUp** | `VK_PAGEUP = 0x21` |
| 아래로 | **PageDown** | `VK_PAGEDOWN = 0x22` |
| 맨 위 | Home | `VK_HOME = 0x24` |
| 맨 아래(최신) | **End** | `VK_END = 0x23` |

### 왜 키보드인가

카카오톡은 **화면에 로드된 범위만** `Ctrl+A` 복사에 포함됩니다.
그래서 읽기 전에 PageUp으로 스크롤해 로드 범위를 늘려야 합니다.

**PageUp 1회 ≈ 30건 추가 로드** (실측: 70 → 100 → 129 → 159)
→ 100건을 넘기려면 PageUp을 **2~3회 이상** 눌러야 합니다.

### 구현 규칙 (중요)

1. **먼저 대화 본문을 클릭**해 포커스를 준다 (`focus_chat`).
   - 클릭 위치는 창 높이의 **45%** 지점. 입력창·이모티콘 버튼을 피한다.
2. PageUp/Pagedown 사이에 **1.0~1.1초 대기** (로드 시간 필요).
3. 클릭 없이 키만 보내면 **스크롤이 안 먹는다.**
4. `Ctrl+A` 직후엔 선택 상태가 되므로, 다시 읽을 때 클릭으로 선택을 푼다.

```python
focus_chat(hwnd)                      # 본문 클릭 (45%)
press_key(VK_PAGEUP, times=3, delay=1.1)   # 위로 3페이지
```

## 맥락 파악에 몇 건이 적당한가 — 실측 결론

`테스트 커뮤니티` 방 159건을 계측한 결과:

| 시간 간격 | 대화 세션 수 | 세션당 메시지 |
|---|---|---|
| 갭 > 5분 | 19개 | 6.8건 |
| 갭 > 10분 | 13개 | 9.9건 |
| 갭 > 30분 | 7개 | 18.4건 |
| 갭 > 60분 | 6개 | 21.5건 |

**한 화제가 완결되는 단위 = 12~15건** (질문 → 답 → 후속질문 → 정리)

### 개수로 자르면 안 되는 이유

| 방법 | 결과 |
|---|---|
| `-n 10` | ❌ "어떤 작업 하시나요?" 질문 도입부가 잘려 맥락 손실 |
| `-n 20` | ⚠️ 화제 1개 완결 + 앞 화제 꼬리 8건(노이즈) 혼입 |
| `--since 6` | ✅ 화제 1개를 **정확히** 잘라냄 (12~13건, 완결) |

→ **시간 기준(`--since`)이 개수 기준보다 정확합니다.**

### 권장 설정

| 상황 | 옵션 |
|---|---|
| **화제 단위 정확히** | `--since 6` (기본 권장) |
| 1:1 방 | `-n 15` |
| 단체방 | `-n 25` ~ `-n 30` |
| 하루치 흐름 | `--since 24 --deep 3` |
| 전체 이력 | `--deep 6` |

## 명령

```bash
python kt.py read "내게쓴방" --since 6           # 최근 6시간 (권장 기본)
python kt.py read "내게쓴방" -n 15               # 최근 15건
python kt.py read "방" --deep 3 --since 24   # PageUp 3회 → 하루치
python kt.py read --json                     # JSON
python kt.py read --max-chars 40             # 본문 40자로 자름
python kt.py read --save                     # 원본 로컬 저장 (기본 안 함)
python kt.py open "내게쓴방"                     # 방 열기 + 490×736
python kt.py show                            # 숨긴 메인창 열기 + 667×878
python kt.py send "메시지" --yes              # 전송 (--yes 없으면 dry-run)
python kt.py size                            # 창 크기 점검·강제
python kt.py windows                         # 창 목록
```

## 읽기 방식 실측 비교 (490×736)

| 방식 | 소요 | 글자수 | 정확도 |
|---|---|---|---|
| **클립보드 전사** | **0.35초** | 853자 | **100%** ← 채택 |

## 안전 규칙

- **`Escape` 금지** — 방 또는 앱 전체가 닫힙니다.
- 방 닫기는 `WM_CLOSE` (방만 닫히고 앱 생존 — 검증 완료).
- 클립보드는 백업 후 복원.
- 전송은 `--yes` 없으면 dry-run.
- 실제 사람 방에 테스트 메시지 금지. 테스트는 '나와의 채팅'에서만.
- 클릭은 창 높이 45% 지점 고정 (이모티콘 버튼 오클릭 방지).

# kt_watch.py — @라온아 트리거 워처

새 메시지를 폴링해 **트리거로 시작하는 메시지에만** 자동 응답한다.
`agent-desktop` 본체와 분리된 사이드카이며, `kt.py`의 검증된 읽기/쓰기 경로를 그대로 쓴다.

## 기본 문법

```bash
# 반응 대상만 확인 (전송 안 함)
python kt_watch.py --room "방이름" --once --dry-run

# 실제 응답
python kt_watch.py --room "방이름" --yes

# 폴링 주기 5초, 최대 100건 응답
python kt_watch.py --room "방이름" --yes --interval 5 --max-replies 100
```

## 트리거

기본값 `@라온아`, `@라온`. 본문이 트리거로 **시작**할 때만 반응한다.

```bash
--triggers "@라온아,@라온,라온아"   # 목록 변경
```

`@라온아.. 시간` 처럼 구두점이 붙어도 뒤 명령만 추출된다.

## 내장 명령

| 보낸 메시지 | 응답 |
|---|---|
| `@라온아` / `@라온아 안녕` | 인사 + 대기 상태 |
| `@라온아 시간` | 현재 시각 |
| `@라온아 상태` | 가동시간·폴링·감지·응답 수 |
| `@라온아 도움말` | 명령 목록 |
| `@라온아 최근` | 최근 3건 요약 |
| `@라온아 원문` | 받은 원문 그대로 |
| 그 외 | 접수 확인 |

## LLM 연결 (hook)

`--hook`에 명령을 주면 자유 대화가 가능하다.
**stdin = JSON, stdout = 응답** 규약이다.

```python
# llm_hook.py
import json, sys
req = json.load(sys.stdin)          # {"text","raw","room","sender","time","recent"}
reply = my_llm(req["text"])         # 여기에 실제 모델 호출
print(reply)
```

```bash
python kt_watch.py --room "방이름" --yes --hook "python llm_hook.py"
```

## 안전장치

- 기본이 **dry-run**. `--yes` 없으면 절대 전송하지 않는다.
- `--me "내닉네임"`으로 내 메시지 무시 (자기 루프 차단)
- 방 이름 == 발신자(나와의 채팅)도 자동으로 내 메시지로 간주
- 보낸 응답 원문을 즉시 `seen`에 등록 → 재감지 차단
- 같은 발신자에게 `--cooldown`(기본 3초) 내 재응답 금지
- `--max-replies`(기본 50) 초과 시 자동 정지
- **Escape 키를 쓰지 않는다** (앱 종료 위험)

## 상태

`_watch_state.json` — 감지한 메시지 지문(최근 400개) + 누적 응답 수.
재시작해도 과거 메시지에 다시 반응하지 않는다.
`_watch.log` — 실행 로그.
`--reset-state` — 지문 초기화.

## 테스트 모드 (나와의 채팅)

`내게쓴방` 같은 1:1 나와의 채팅은 발신자가 곧 방 이름이라 기본적으로 자기 메시지로 걸러진다.
테스트할 때만 `--allow-self`를 붙인다.

```bash
python kt_watch.py --room "내게쓴방" --once --dry-run --allow-self
```

# 운영 설정 — 테스트 커뮤니티 전용

## 실측으로 확인한 값

| 항목 | 값 |
|---|---|
| 실제 방 이름 | `테스트 커뮤니티` (호출은 `테스트 커뮤니티`로 매칭) |
| 내 닉네임 | `내닉네임` |
| 방 창 크기 | `490×736` |
| 폴링당 읽기 | `25`건 |

**내 메시지도 클립보드 전사에는 발신자가 붙는다.**
`내닉네임 (오전 2:24) @라온아 도움말` 처럼 나온다.
그래서 발신자 이름으로 자기 메시지를 걸러낼 수 있다.

## 운영 실행

```bash
python kt_watch.py --room "테스트 커뮤니티" \
  --me "내닉네임" \
  --triggers "@라온아,@라온" \
  --interval 5 --cooldown 5 --max-replies 30 --window 25 --yes
```

또는 `watch_vibe.cmd` 더블클릭.

## 검증 기록 (실측)

| 시각 | 검증 내용 | 결과 |
|---|---|---|
| 02:23:42 | `--me` 필터 (감지 1건, 트리거 0건) | 내 메시지 무시 ✅ |
| 02:24:10 | 트리거 감지 + dry-run 응답 생성 | ✅ |
| 02:24:16 | 재감지 시도 | 중복 차단(감지 0건) ✅ |
| 02:24:50 | 실제 전송 | 방에 응답 도착 ✅ |
| 02:24:58 | 전사 재확인 | `[SEND]` 문구가 방에 실제 표시됨 ✅ |

## 주의

- 이 방은 **실제 사람이 있는 단톡방**이다. 응답은 짧고 정중하게 유지할 것.
- `--max-replies 30`으로 폭주를 막는다. 넘으면 자동 정지.
- 워처가 도는 동안 카카오톡 창을 직접 만지면 클립보드·스크롤이 충돌할 수 있다.
- 중지: 실행 창에서 `Ctrl+C` 또는 프로세스 종료.
- `_watch_state.json`에 지문이 쌓여 재시작해도 과거 메시지에 다시 반응하지 않는다.
